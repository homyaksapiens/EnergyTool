# Контракты команды

Здесь зафиксировано, как части проекта общаются друг с другом. Каждый работает в своей зоне и опирается
на эти интерфейсы, а не на детали чужого кода. Фронт не ждёт бэкенд, бэкенд не ждёт бота: до готовности
соседа работаем на заглушках по примерам ниже.

**Как менять контракт:** отдельный PR с правкой этого файла и кода, апрув владельца каждой затронутой части.
Добавить поле — можно сразу, если старые клиенты не ломаются. Переименовать или удалить — только по договорённости.

## 1. Зоны ответственности

| Зона | Папки и файлы | Владелец |
|---|---|---|
| Бот, поиск, сабмиты | `bot/`, `eval/`, `scripts/`, `SUBMISSIONS.md` | _имя_ |
| Веб: бэкенд и фронтенд | `backend/`, `frontend/`, `Dockerfile`, `compose.yaml` | _имя_ |
| Сценарии, документация, защита | `docs/`, `README.md`, презентация | _имя_ |

`CLAUDE.md` и `CONTRACTS.md` — общие: правки через PR, апрув всех.

## 2. Ядро консультанта: `bot/` → бэкенд

Бэкенд добавляет `bot/` в `sys.path` и импортирует модули напрямую. Ядро создаётся один раз при старте:

```python
import llm_client
from consultant import Consultant
from kb import KnowledgeBase, load_documents

kb = KnowledgeBase(load_documents(KB_PATH))   # путь к knowledge-base.zip
kb.enable_dense(llm_client.embed)             # необязательно; при ошибке работаем на BM25
consultant = Consultant(kb)
```

Вызов на каждую реплику клиента:

```python
result = consultant.answer(messages)
```

- `messages` — история **текущей** сессии: `[{"role": "user" | "assistant", "content": str}, ...]`, последняя — `user`
- вызов синхронный (httpx), в FastAPI — из обычного `def`-эндпоинта, он сам уйдёт в пул потоков
- настройки модели и поиска — из переменных окружения (раздел 6)

Результат:

| Поле | Тип | Что значит |
|---|---|---|
| `text` | `str` | ответ клиенту, обычный текст без markdown |
| `fallback` | `bool` | `true` — модель не ответила, в `text` запасная фраза |
| `reranked` | `bool` | фрагменты отобраны реранкером |
| `sources` | `list[{source, title}]` | фрагменты базы знаний, переданные модели, по порядку |
| `timings` | `{retrieval, llm}` | время этапов в секундах |

Планируется (v2, владелец бота):
- `offer_lead: bool` — пора предложить связаться с менеджером
- `consultant.summarize_lead(messages) -> str` — резюме для заявки в формате раздела 4.3

Ограничение: в `bot/` только плоские `.py` и зависимости из `данные/requirements.txt` — эта папка целиком уходит в ZIP сабмита.

## 3. Сабмит на платформу

Формат входа и выхода, лимиты и переменные задаёт регламент (`техчать.md`), это не обсуждается. Наши правила:
- ZIP собирается только скриптом `scripts/make_zip.py` (он же проверяет пакеты, ключи и состав архива)
- перед сабмитом — `eval/run_local.py` на всех демо-вопросах, без запасных ответов
- 5 сабмитов в день на всю команду: решение об отправке принимает владелец бота, каждый сабмит — строка в `SUBMISSIONS.md`

## 4. HTTP API бэкенда: бэкенд → фронтенд

Бэкенд раздаёт фронтенд и API с одного адреса: `http://localhost:8000`. Всё в JSON, UTF-8.
Ошибки — HTTP 4xx/5xx с телом `{"detail": "текст для человека"}`.

### 4.1. Диалог

`POST /api/sessions` → `201` — кнопка «Новый диалог». Старая сессия остаётся в истории.
```json
{"session_id": "8f3c…"}
```

`POST /api/chat` — реплика клиента. Без `session_id` создаётся новая сессия; неизвестный `session_id` → `404`
(фронт начинает новый диалог).
```json
{"session_id": "8f3c…", "message": "У нас несколько магазинов. Можно смотреть их расход в одном кабинете?"}
```
→ `200`
```json
{
  "session_id": "8f3c…",
  "answer": "Да, платформа подходит сетевому ретейлу: …",
  "offer_lead": false,
  "debug": {
    "elapsed_ms": 4210,
    "timings": {"retrieval": 0.05, "llm": 4.1},
    "fallback": false,
    "sources": [{"source": "20-products/22-askue.md", "title": "Облачная платформа учёта электроэнергии → Кому подходит"}]
  }
}
```
`debug` приходит всегда; фронт показывает его только в режиме отладки (переключатель в интерфейсе).

### 4.2. История сессий (для проверки жюри)

`GET /api/sessions` → список всех сессий, в том числе без заявки, новые сверху:
```json
[{"session_id": "8f3c…", "created_at": "2026-11-10T12:00:00+03:00", "updated_at": "…", "messages": 6, "lead_id": null,
  "preview": "У нас несколько магазинов…"}]
```

`GET /api/sessions/{session_id}` → сессия целиком:
```json
{"session_id": "8f3c…", "created_at": "…", "lead_id": null,
 "messages": [{"role": "user", "text": "…", "created_at": "…"},
              {"role": "assistant", "text": "…", "created_at": "…", "debug": {"elapsed_ms": 4210, "sources": []}}]}
```

### 4.3. Заявки

`POST /api/leads` — клиент оставил контакты (форма в чате, которую фронт показывает по `offer_lead` или по кнопке):
```json
{"session_id": "8f3c…", "full_name": "Иванов Иван Иванович", "phone": "+7 900 000-00-00",
 "company": "ООО «Пример»", "consent": true}
```
→ `201` `{"lead_id": 12, "summary": "…"}`. Нет согласия или неверный телефон → `422` с объяснением в `detail`.

`GET /api/leads` → заявки, новые сверху:
```json
[{"lead_id": 12, "created_at": "…", "session_id": "8f3c…", "full_name": "…", "phone": "…", "company": "…",
  "summary": "…", "status": "new"}]
```

`PATCH /api/leads/{lead_id}` `{"status": "new" | "in_progress" | "done" | "rejected"}` → `200` `{"ok": true}`

Резюме для менеджера (`summary`) — markdown с постоянными разделами:
```
**Клиент:** ФИО, компания, телефон
**Задача:** что хочет решить, своими словами клиента
**Что выяснили:** тип объекта, масштаб, как ведётся учёт, ценовая категория, мощность — что прозвучало
**Подходящие решения:** продукты EnergyTool и почему
**Открытые вопросы:** что не успели выяснить
**Следующий шаг:** расчёт, демо, пилот…
```

### 4.4. Служебное

`GET /api/health` → `{"ok": true, "model": "…", "kb_chunks": 236, "dense": false}`

## 5. Хранение

SQLite, файл `DB_PATH` (по умолчанию `data/app.db`, в Docker — volume). Пишет только бэкенд.
- `sessions` — `id, created_at, updated_at`
- `messages` — `id, session_id, role, text, created_at, debug` (JSON, только у ответов бота)
- `leads` — `id, session_id, created_at, full_name, phone, company, summary, status`

Персональные данные в тестах — только выдуманные.

## 6. Переменные окружения и порты

Образец — `.env.example`. Секреты только в `.env`, он не коммитится.

| Переменная | Кто читает | Что это |
|---|---|---|
| `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` | бот | OpenAI-совместимый сервер; локально — LM Studio `http://localhost:1234/v1` |
| `EMB_MODEL`, `RERANKER_MODEL` | бот | модели эмбеддингов и реранкера; нет модели — бот работает без неё |
| `ET_*` | бот | тонкая настройка поиска и времени, список — в `bot/settings.py` |
| `KB_PATH` | бэкенд | путь к `knowledge-base.zip`, по умолчанию `данные/knowledge-base.zip` |
| `DB_PATH` | бэкенд | файл SQLite, по умолчанию `data/app.db` |
| `PORT` | бэкенд | порт, по умолчанию `8000` |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | бэкенд | уведомления менеджеру, необязательно |

## 7. Git

- `main` всегда рабочий: из него в любой момент собирается сабмит и запускается демо
- работа — в ветках `bot/…`, `web/…`, `docs/…` (например, `bot/query-rewrite`), одна ветка — одна задача
- небольшие PR, ревью хотя бы одним человеком; мержит автор после апрува
- перед PR: подтянуть свежий `main`; бот — прогон `eval/run_local.py` без запасных ответов; веб — основной сценарий
  в браузере (вопрос → ответ → заявка → заявка видна менеджеру)
- коммиты по-русски, с зоной в начале: «Бот: переформулировка запроса для диалогов»
- не коммитить `данные/`, `data/`, `runs/`, `dist/`, `.env` — они в `.gitignore`
