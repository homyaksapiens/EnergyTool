# EnergyTool — ИИ-консультант для сайта МТС

Консультант помогает предпринимателям и специалистам по энергетике разобраться в продуктах МТС EnergyTool. Он отвечает по базе знаний, уточняет задачу в диалоге и по запросу передаёт менеджеру заявку с контактами и резюме разговора.

## Запуск через Docker

1. Установите Docker с Docker Compose. Откройте терминал в корне репозитория.
2. Создайте локальный файл `.env` на основе `.env.example`. В PowerShell выполните `Copy-Item .env.example .env`, в Bash — `cp .env.example .env`.
3. Поместите оригинальный архив `knowledge-base.zip` из материалов кейса в `data/knowledge-base.zip`. Создайте папку `data`, если её ещё нет. Compose подключает архив к контейнеру только для чтения.
4. Для генерации ответов заполните `LLM_BASE_URL`, `LLM_API_KEY` и `LLM_MODEL` по инструкции ниже.
5. Соберите и запустите приложение одной командой.

```bash
docker compose up --build
```

Сайт доступен на [http://localhost:8000](http://localhost:8000), описание API — на [http://localhost:8000/docs](http://localhost:8000/docs). Порт хоста можно изменить через `PORT` в `.env`. Контейнер слушает порт 8000, Compose публикует его на loopback хоста. SQLite хранится в томе `app-data` и сохраняется при обычном `docker compose down`.

## Подключение модели

- **Прокси организаторов** использует OpenAI-совместимый API. Укажите выданный адрес в `LLM_BASE_URL`, ключ в `LLM_API_KEY`, идентификатор Qwen3.8-27B из конфигурации прокси в `LLM_MODEL`. Для поиска доступны BAAI/bge-m3 и Qwen3 Reranker 8B. Укажите идентификаторы из конфигурации в `EMB_MODEL` и `RERANKER_MODEL`.
- **Локальная проверка** возможна с OpenAI-совместимым сервером, например LM Studio. Запустите сервер и загрузите модель. При запуске через Docker Desktop укажите `LLM_BASE_URL=http://host.docker.internal:1234/v1` и точный идентификатор загруженной модели в `LLM_MODEL`. Укажите ключ, если локальный сервер требует аутентификацию. На Linux используйте адрес сервера, доступный из контейнера.
- Для сервера, который поддерживает только генерацию, задайте `ET_USE_DENSE=0` и `ET_USE_RERANK=0`. Поиск будет работать по BM25.

| Переменная | Назначение |
| --- | --- |
| `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` | Адрес совместимого API, ключ и ID генеративной модели. |
| `EMB_MODEL`, `RERANKER_MODEL` | ID моделей поиска. Если оставить пустыми, ядро использует `baai/bge-m3` и `qwen/qwen3-reranker-8b`. |
| `ET_USE_DENSE`, `ET_USE_RERANK` | Включают векторный поиск и реранжирование соответственно. Значения `1` или `0`. |
| `PORT` | Порт хоста, по умолчанию `8000`. |
| `DEMO_AUTH` | `1` включает выбор тестового аккаунта, `0` включает гостевой режим. |
| `MANAGER_USER`, `MANAGER_PASSWORD` | HTTP Basic для менеджера при `DEMO_AUTH=0`. Логин по умолчанию `manager`. Для защиты панели задайте пароль. |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | Необязательные уведомления о заявках. Для проверки достаточно панели менеджера. |

При запуске через Compose пути `KB_PATH` и `DB_PATH` заданы в конфигурации контейнера. Рабочие ключи указываются только в локальном `.env`.

## Порядок проверки

1. Откройте [сайт в режиме отладки](http://localhost:8000/?debug=1). При включённом демовходе выберите аккаунт из раздела «Пользователи».
2. Откройте чат и спросите, например, «У нас три магазина и выросли счета за электричество. Чем может помочь EnergyTool?». Ответьте на уточняющий вопрос. Включите показ отладки в левой колонке чата и проверьте источники из базы знаний и время ответа.
3. Нажмите «Оставить заявку» в чате. Проверьте ФИО, телефон и компанию, дайте согласие и нажмите «Отправить заявку». Используйте вымышленные контакты или данные демоаккаунта. После отправки появится номер заявки.
4. Нажмите «Новый диалог», задайте ещё один вопрос и оставьте диалог без заявки. Закройте чат и откройте снова. Чат начнёт новый разговор, а прежние сессии будут доступны в истории.
5. Выйдите из аккаунта клиента и выберите аккаунт из раздела «Администраторы». В [панели менеджера](http://localhost:8000/manager) найдите заявку, проверьте контакты, резюме, переписку и смените статус. В истории проверьте диалог без заявки.
6. Если приложение запустилось, [`/api/health`](http://localhost:8000/api/health) показывает `ok`, имя настроенной модели, число фрагментов базы и состояние векторного индекса. Для проверки доступности самой модели отправьте вопрос в чат.

## Архитектура и зависимости

- `frontend/` — сайт, чат и панель менеджера на HTML, CSS и JavaScript. Их раздаёт тот же FastAPI, который обслуживает запросы.
- `backend/` — FastAPI и SQLite. Бэкенд хранит сессии и сообщения, проверяет роли демоаккаунтов, создаёт заявки и формирует резюме. Тесты HTTP API находятся в `backend/tests/`.
- `bot/` — ядро версии на 64 балла. Оно выделяет запрос из истории, находит фрагменты базы через BM25 и, при доступности, эмбеддинги и реранкер, затем передаёт выбранные фрагменты генеративной модели.
- `eval/` и `scripts/` — локальный прогон на демовопросах и сборка отдельного архива для автоматической оценки.

Образ использует Python 3.13. Версии FastAPI, Uvicorn, Pydantic, python-dotenv, HTTPX и NumPy закреплены в `backend/requirements.txt`. Зависимости отдельной точки входа для автоматической оценки закреплены в `bot/requirements.txt`. Для фронтенда отдельная сборка не нужна.

## Ограничения

- Для запуска нужен архив базы знаний организаторов. Он подключается отдельно от репозитория и образа.
- Для содержательной консультации нужен доступ к серверу модели. При сбое генерации чат сообщает об ошибке или возвращает запасной ответ. При сбое эмбеддингов поиск продолжает работать по BM25.
- Демовход позволяет выбрать одну из вымышленных учётных записей без проверки личности. Используйте его в локальной среде с тестовыми данными. Настоящая авторизация МТС и интеграция с CRM требуют отдельной настройки.
- Запросы модели могут занимать десятки секунд. Сессии хранятся в SQLite до 30 дней.
